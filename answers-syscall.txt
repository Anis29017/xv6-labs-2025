Q2.What is the value of p->trapframe->a7 and what does that value represent? (Hint: look at user/init.c, the first user program xv6 starts, and its compiled assembly user/init.asm.)

Ans. 
The value of p->trapframe->a7 is 0x11 (decimal 17).
This represents the system call number for mknod, which the init process executes to create device files such as /dev/console during early boot.

Q3.What was the previous mode that the CPU was in?
Ans.
p /x $sstatus = 0x200000022. The SPP bit (bit 8) is 0, so the CPU was previously in user mode.


Q4.Write down the assembly instruction the kernel is panicing at. Which register corresponds to the variable num?
Ans.
The kernel panics at instruction address 0x80001cee, where it executes
lw a3,0(zero) — a load from memory address 0.
This corresponds to the C statement num = *(int *)0;.
The register corresponding to num is a3.


Q5.Why does the kernel crash? Hint: look at figure 3-3 in the text; is address 0 mapped in the kernel address space? Is that confirmed by the value in scause above? (See description of scause in RISC-V privileged instructions)
Ans.
The kernel crashes because it tries to dereference the null pointer (*(int *)0), i.e., access memory address 0, which is not mapped in the kernel address space. This causes a load page fault (scause = 0xd, stval = 0x0), leading xv6 to panic with kerneltrap.
